# ADR 008：以可恢复的生命周期交付

日期：2026-11-13。

S5 将授权管理移到用户可操作界面，同时在事务内重新读取当前管理员或对象管理权限。知识库可见范围与 ACL 整体更新；文档 ACL 只能进一步收紧。成员停用和角色变更通过现有 ACL epoch 联动运行和引用。取消请求使用独立速率范围，普通 API 限流不能阻止所有者停止运行。

文档解析使用固定子进程，ZIP 目录及正文解析均在其中执行；父进程负责墙钟、取消、输出和回收，Linux rlimit 限制 CPU/地址空间/文件输出。子进程不继承应用凭据，部署容器采用只读根目录和临时空间资源上限。Windows 本地路径只承诺实际实现的墙钟/输出控制，不能把 Linux 限制算作 Windows 验收结果。

孤儿文件使用延迟的两次观察，上传使用先落库的对象租约，清理与上传提交按租户加锁。任何不可变版本仍引用的文件都保留。软删除、业务历史、费用账本和原文件物理回收分别处理，避免清理破坏引用与可恢复性；临时目录和过期技术凭据另行清理。

PostgreSQL custom dump 与对象快照通过暂停应用写入取得一致集合，恢复仅允许全新 project/数据库/空对象空间。文件哈希与规范化业务行摘要在新服务启动前核对，再执行业务回归。源环境不被恢复脚本覆盖。

验收按 A01–A15 分项给出实际证据与处理决定。持续并发、重复故障和恢复用真实容器执行，规则模型/协议替身与真实模型质量明确区分。没有实际供应商和人工复核的项目保持待验收，不使用目标数字替代结果。

参考：[Python subprocess 超时与回收](https://docs.python.org/3.12/library/subprocess.html)、[Linux/Unix resource 限制](https://docs.python.org/3.12/library/resource.html)、[PostgreSQL custom dump](https://www.postgresql.org/docs/17/app-pgdump.html)。
