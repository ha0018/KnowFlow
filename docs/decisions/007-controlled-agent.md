# ADR 007：模型提议，服务端限定执行

日期：2026-11-13。

S4 使用原生 Chat Completions function calling，将模型输出视为不可信调用建议。服务端维护唯一的三个只读函数及严格 schema；用户、租户、ACL、会话范围与执行预算由服务器取得。每轮只允许一个调用，最多四次执行，重复参数/调用 ID 或额外调用停止。模型不能生成任意 Python、SQL、Shell、文件或 URL 操作。

同步函数外包裹 asyncio 超时不能终止其真实工作，因此每个工具运行在固定入口的新子进程中。父进程控制启动与通信期限，超时/取消先 kill/wait，再处理审计和未知用量。总活动执行限定 60 秒、单工具 10 秒；终态清理时间另计。该方案终止可信应用函数，不宣称提供不可信代码资源沙箱。

复用 Run(kind=agent)、MessageReference、ToolCall 和 S2 用量账本，避免另一套身份/额度逻辑。以租户锁保证整轮 Token 预留；调用前后、证据入库和最终提交检查最新权限/发布版本。数据库冻结 run.kind、工具归属与参数标识，工具 actor 必须等于 run.user。统计快照通过 ToolCall 的 source_id/result_summary 保存，统一 S 编号并保守使用 ACL epoch 失效。

工具观察有累积字节预算，最终回答只接受实际已收集的引用编号。原子保存最终正文后再发 SSE delta，避免撤权后暴露尚未提交的最终答案。规划使用非流式有界 JSON；前端展示工具进度，不展示内部推理，也不宣称 Agent 上游逐 Token 生成。普通 RAG 保留已有流式路径。

默认规则演示、真实子进程和本地实际 HTTP 替身用于验证执行边界。真实供应商的工具选择、复杂规划、注入抵抗和语义引用效果需独立验收；引用编号有效不等于事实已被来源支撑。
