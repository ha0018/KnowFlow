# 实现范围与后续验收

本项目根据技术方案构建，交付的是可运行开发基线。技术方案中的八周目标不是此次交付的测试结论。

| 领域 | 当前交付 | 未完成/待验收 |
| --- | --- | --- |
| 身份/权限 | 单租户账号、JWT、角色、KB/文档 ACL、数据库关联隔离 | 组织树、SSO、RLS；成员/授权管理主要通过 API |
| 文档 | 四种格式、版本、任务、租约/fencing、发布、软删除 | 批量上传、HTML/XLSX、OCR、解析沙箱、后台孤儿文件回收/物理清理 |
| 检索 | SQLite 有界精确示例；PG pgvector + 中文 FTS + RRF | 真模型召回校准、HNSW、Reranker、Query Rewrite、BM25 对照 |
| 问答 | 引用、流式、取消、撤权隐藏、幂等、预算内的授权历史重放、独立模型配置与探测、原子额度预留/结算、调用价格快照 | 真实供应商闭环与质量/时延实测、供应商 tokenizer 校准 |
| 工具 | 三个显式只读工具、严格参数校验、租户审计 | 自主模型规划、四步 runner、单工具硬超时、整个 Agent 预算 |
| 评估 | 20 条自编开发题、文档召回及 MRR、版本检查 | 100 条分层保留集、EvidenceHit、人工回答支撑率、正式基线/消融 |
| 工程 | 锁文件、镜像 digest/源码校验、受限应用账号、完整 Compose CI、真实 Redis/Celery/MinIO 闭环、依赖停机恢复、健康检查、SQLite 备份恢复 | 部署环境的 PostgreSQL/对象存储备份恢复、TLS、长期运行及压力验收 |
| 性能 | 未声明业务延迟/质量指标 | 技术方案 A01–A15 的完整安全矩阵、压力测试、故障演练和实测报告 |

默认哈希 Embedding 仅用来展示向量、索引、授权和排序机制，不提供真实语义理解。演示回答逐字摘录原文，界面明确标识；不能用于宣称 LLM 效果。

2026-11-06 已完成 [S1 基础设施阶段](development-plan.md)，八组容器业务检查及两项依赖故障恢复通过，证据见 [CI](https://github.com/ha0018/KnowFlow/actions/runs/42160359237) 与 [原始报告](benchmarks/infrastructure-2026-11-06.json)。

S2 的代码与自动验收已完成，支持独立地址/密钥、限额、重试、超时、取消、未知用量记录和历史重放；[供应商接入验收](model-integration.md) 待真实配置。当前受控 HTTP 协议测试不代表真实供应商验证。

本地解析器限制文件/页数/解压体积/文本体积；生产环境仍需要独立进程或容器限制 CPU、内存与时间。工具的时限当前为结果返回前的时长检查，不能中断已经在执行的同步函数。

待执行验收时应冻结真实模型、语料、硬件、并发与配置，保存原始结果。没有证据的性能和质量数字不能写成项目成果。
